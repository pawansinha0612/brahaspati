Website Change Monitor

Get told when a web page changes — a competitor’s prices, a supplier’s terms, a government form, or your own site breaking. It runs free on GitHub, takes a screenshot on a schedule, compares it with last time and opens an issue (which emails you) when something changes.

Why GitHub, and not this page?

A web page can’t keep watching other websites once you close the tab, and this site has no server. So this page writes three small files for you, and GitHub Actions (free) runs them on GitHub’s computers on your schedule. You need a free GitHub account; no coding, no credit card.

  • Cost: free. Public repositories get unlimited Actions minutes; private ones get 2,000 free minutes a month, and each check takes about 1–2 minutes.
  • Privacy: screenshots are saved in the repository. Make it private unless you don’t mind others seeing them.
  • Honest limits: scheduled runs can start 5–30 minutes late at busy times. In a public repository with no activity for 60 days GitHub pauses the schedule and emails you — click “Enable workflow” to restart. Pages behind a login, CAPTCHA or bot-blocking may not load.

3. Set it up on GitHub (about 10 minutes)

  1. Go to github.com and sign in (or create a free account).
  2. Click the + at the top right → New repository. Name it e.g. page-monitor, choose Private, tick Add a README file, then Create repository.
  3. In your new repository click Add file → Create new file. In the name box type .github/workflows/page-monitor.yml (typing the / makes the folders). Copy the Workflow file above, paste it in, then click Commit changes… → Commit changes.
  4. Again Add file → Create new file, name monitor/monitor.js, paste the monitor.js file, commit.
  5. Once more: name monitor/urls.json, paste the urls.json file, commit.
  6. Click the Settings tab → Actions → General. Under Workflow permissions choose Read and write permissions and Save. (This lets it save screenshots and open issues using GitHub’s built-in token — no passwords needed.)
  7. Click the Actions tab. If asked, click I understand my workflows, go ahead and enable them. Choose Page monitor on the left → Run workflow → Run workflow.
  8. The first run takes about 2 minutes and saves the starting screenshots in monitor/data. From then on it compares each run with the one before. When something changes you’ll get a new Issue with before/after/difference pictures.
  9. To get emails: click Watch (top of the repository) → All Activity, or Custom → Issues. Check your GitHub email settings under your profile → Settings → Notifications.

To change pages later, edit monitor/urls.json on GitHub (pencil icon). To stop, go to Actions → Page monitor → ••• → Disable workflow. If a run fails, open it in the Actions tab — the red step shows what went wrong.
